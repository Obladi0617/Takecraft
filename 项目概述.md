# AI Film Agent：多智能体 AI 短片生产工作流系统  
## 项目系统设计与开发规格书 v1.0

---

# 0. 文档定位

本文档定义一个面向 AI 短片制作的 **Local-first 多智能体影视生产工作台**。

系统目标不是简单实现：

> Prompt → Video

而是把一套完整的 AI 影视生产方法固化为可持续运行、可暂停、可修改、可回溯、可重新生成的 Agent 工作流：

```text
Idea / 人机讨论
        ↓
剧本
        ↓
角色 / 场景资产
        ↓
导演方案
        ↓
Storyboard
        ↓
Shot
        ↓
多 Take 抽卡
        ↓
AI Review
        ↓
用户 / Agent 选片
        ↓
Editor Agent
        ↓
Timeline
        ↓
实时 Preview
        ↓
Final Render
```

本文档只讨论 **系统、工作流、架构和实现**。

暂不讨论：

- 最终参赛短片具体讲什么
- 短片具体艺术风格
- 最终成片剧情
- 获奖题材策略

---

# 1. 项目定位

## 1.1 一句话定义

> 一个本地优先、跨平台运行的 AI 影视生产 Agent 系统，将编剧、导演、制片、分镜、视频生成、审核、抽卡选片和剪辑组织成一套可交互的持续生产工作流。

---

# 2. 核心设计原则

## 2.1 Local-first

除 AI 模型 API 与远程视频生成服务器外，核心业务全部在用户本机完成：

```text
本机
├─ Web UI
├─ Agent Workflow
├─ 项目数据库
├─ 项目文件
├─ 素材
├─ Shot / Take 数据
├─ Timeline
├─ Proxy
├─ Preview
├─ FFmpeg
└─ Agent State

外部
├─ LLM API
├─ VLM / Video Review API
└─ DGX Spark 视频生成
```

---

## 2.2 Workflow First

系统核心不是聊天窗口，而是：

```text
Production State
+
Agent Workflow
+
Human-in-the-loop
```

其中：

**Human-in-the-loop** 指 Agent 可以自主执行，但在关键创作节点允许用户介入、覆盖或修改决策。

---

## 2.3 Structured State

Agent 不应主要通过自然语言互相传递状态。

核心生产状态必须结构化存储，例如：

```text
Project
Scene
Character
Location
Shot
Storyboard
Take
Review
Timeline
GenerationJob
```

Agent 只负责：

- 推理
- 建议
- 决策
- 调用工具

生产事实由数据库负责。

---

## 2.4 Model Agnostic

业务层不得绑定具体模型。

系统只依赖统一接口：

```text
TextModel
VideoUnderstandingModel
ImageGenerator
VideoGenerator
```

因此后续可以替换：

```text
OpenAI
Claude
Gemini
Qwen
MiniMax
Wan
Z-Image
Qwen-Image
其他模型
```

# 5. 两种工作模式

系统支持两种模式，并允许项目运行过程中切换。

---

## 5.1 Auto Mode

目标：

> 用户提供一句话或经过讨论的创意后，Agent 最大程度自主完成生产。

基本流程：

```text
Idea
↓
Producer
↓
Writer
↓
Director
↓
Assets
↓
Storyboard
↓
Shot Generation
↓
Reviewer
↓
Auto Select
↓
Editor
↓
Timeline
↓
Preview
```

只有以下情况强制 interrupt：

```text
生成连续失败
Reviewer 超过自动重抽上限
必要资产缺失
用户设置必须确认
严重模型异常
```

---

## 5.2 Director Mode

允许用户在任意生产阶段介入：

```text
修改剧本
修改 Shot
修改 Prompt
重抽 Storyboard
锁定分镜
设置 Take 数量
选择 Take
重新生成
修改 Timeline
覆盖 Editor 决策
```

# 12. 自动重抽机制

Reviewer 可以触发自动重抽。

但必须限制：

```text
max_auto_retake_rounds = 2
```

默认规则：

```text
第一次失败
↓
Reviewer Diagnose
↓
Prompt Agent Modify
↓
重新生成

第二次失败
↓
Reviewer Diagnose
↓
再次修改

仍失败
↓
Interrupt
↓
交给用户
```

用户可以：

```text
继续抽
改 Prompt
换 Storyboard
直接选已有 Take
取消 Shot
```

# 24. DGX Spark 调度

当前硬件条件：

```text
单台 DGX Spark
主要承担视频生成
```

因此：

```text
batch_size = 3~5
```

含义：

> 每批进入系统的 Shot 数量。

不是：

> GPU 同时跑 5 条视频。

---

默认：

```text
video_generation_concurrency = 1
```

即：

```text
单 Video Worker
```

以后实测允许：

```text
2
```

则仅修改配置。

# 25. Pipeline 并行策略

GPU 视频生成可以串行。

但：

```text
Prompt
Review
Agent
Asset Processing
Proxy
UI
```

都可以并发。

例如：

```text
Shot 01 → Video Generation
Shot 02 → Prompt Ready
Shot 03 → Storyboard Review
Shot 04 → Waiting
```

当 Shot 01 生成完成：

```text
Shot 01 → Cloud Reviewer
Shot 02 → GPU Generation
```

确保 GPU 持续工作。

# 74. 项目最终验收定义

一个用户能够：

1. 在任意 Windows / macOS / Linux 机器启动系统；
2. 创建本地项目；
3. 通过一句话或人机讨论构建项目；
4. 创建并锁定角色与场景资产；
5. 生成每个 Shot 的 Storyboard；
6. 为每个 Shot 生成任意数量 Take；
7. 查看每个 Take 对应 Prompt、模型和参数；
8. 获得 AI Reviewer 审核；
9. 允许 Reviewer 有限自动重抽；
10. 用户随时选择任意 Take 作为当前 Shot 版本；
11. Editor Agent 能自动生成 Timeline；
12. 用户可以人工修改 Timeline；
13. 切换 Take 后能够立即实时 Preview；
14. 最终使用 FFmpeg 输出完整视频；
15. 退出程序后所有生产状态能够恢复；
16. 更换生成模型时无需修改核心业务层。

以上全部达到，则 v1 系统完成。
